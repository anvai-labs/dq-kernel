== Purpose

Wrap Soda Core so that SodaCL checks — the checks many data teams already
have — run over their warehouse and land in the same evidence stream as
everything else.

== In scope

* `dq/engine/soda/`: an engine on the ADR-012 hooks.
* Payload: a SodaCL check set as a YAML mapping. Data source and connection
  come from the engine configuration, with credentials from the environment.
* Results: one outcome per check with its outcome, the measured value where
  Soda reports one, and a bounded diagnostic.
* An optional `soda` extra and live tests against DuckDB in the main test
  lane.

== Out of scope

* Soda Cloud (any hosted product);
* Soda's own alerting and scheduling;
* programmatic checks written in Python.

== Contracts

* Capabilities are declared honestly; Soda's `warn` outcome maps to the
  `warn` criticality.
* The engine imports no Soda package until it is used.
* A skipped check is reported as skipped, never as passed.

== Acceptance gates

* G1 — The live dependency and API check is recorded here: versions
  installed, the calls verified against the real package, the date, and the
  result of co-installing with the other extras.
* G2 — The engine passes the conformance suite (SPEC-011).
* G3 — Live round trips against DuckDB: passing, failing, warning, and
  skipped checks each produce the specified outcomes.
* G4 — An invalid SodaCL document fails closed with Soda's message preserved
  as the cause.
* G5 — A checked-in example rule pack validates and is covered by a test.
