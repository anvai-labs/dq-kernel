= Quickstart
:toc:
:sectlinks.

Five minutes from install to evidence. Failures at any step link to the
link:error-catalog.adoc[error catalog].

== 1. Install

[source,shell]
----
pip install 'dq-kernel[spark,deequ]'
----

Requires Python 3.12/3.13, Java 17, and a Spark 3.5.9 runtime. The portable rules can also
run with no Spark at all: `pip install 'dq-kernel[arrow]'` needs only Python.

== 2. Define rules

[source,hocon]
----
dqframework {
  dqrules = [
    {
      name = "my_rules"
      engine = "deequ"
      dataframes = ["default"]
      checks = [
        { constraint_name = "id_complete", constraint = "isComplete", column = "id", level = "Error" }
      ]
    }
  ]
}
----

Portable alternative: the counts/v1, groups/v1, and ranges/v1 subsets
translate from `isComplete`, `hasCompleteness`, `hasSize`,
`DistinctnessByGroup`, `isNonNegative`, and `isInRange` — see
link:specs/SPEC-004-error-catalog-and-quickstart.adoc[the compatibility
notes] and ADR-005.

== 3. Run

[source,python]
----
from dq.dq_framework import DQFramework

results = DQFramework(spark, config, default_dataframe=df).run()
----

== 4. Read evidence

Each result carries `check`, `success`, and bounded `details`; `build_report`
binds them to dataset and rule-set digests as `dq-report/v1`.

== 5. Persist durably

Add `repository { type = "postgres", schema = "dq" }` and export
`DQ_POSTGRES_DSN`. Provision the evidence schema with `ddl_statements()`
(ADR-006). Gate events reach your notifiers (ADR-008).

== No Spark: the same portable rules over files

A portable rule that names the Arrow adapter runs over a file with no session, no Java and
no cluster, and writes the same `dq-report/v1`:

[source,hocon]
----
{ name = "orders_complete"
  engine = "portable"
  dataframes = ["orders"]
  dataset = "orders"
  snapshot_sha256 = "<64 hex digits of the snapshot these rules were written for>"
  adapter = "arrow"
  plan = [ { constraint = "isComplete", constraint_name = "id_complete", column = "id", level = "Error" } ] }
----

[source,shell]
----
dq-run rules.conf --dataset orders=orders.parquet --report report.json
----

`dq-run` exits 0 when the gate passed, 1 when it failed, and 2 when the rule pack cannot be
run as given -- a rule that needs Spark, a portable rule that does not name the Arrow
adapter -- or pyarrow is missing. Parquet, Arrow IPC, CSV and newline-delimited JSON are
read by the file's extension. link:index.adoc#running-over-files[The operator reference]
has the details; `examples/arrow_rule.conf` is a complete rule pack.
